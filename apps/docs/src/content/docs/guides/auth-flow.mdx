## Fluxo completo

1. Usuário acessa `/login`
2. Preenche email + senha
3. `auth-client` envia para Better-Auth (`apps/web/src/lib/auth-client.ts`)
4. Sessão salva em cookie http-only
5. Header reflete estado logado (menu do usuário)
6. Todas as requests à API levam o cookie automaticamente

## Componentes-chave

| Componente | Caminho | Função |
| --- | --- | --- |
| `auth-client` | `apps/web/src/lib/auth-client.ts` | Cliente Better-Auth |
| `user-menu` | `apps/web/src/components/user-menu.tsx` | Menu do usuário logado (Dashboard, Account Settings, Sign Out) |
| `header` | `apps/web/src/components/header.tsx` | Barra superior em grid centrado; some nas rotas `/dashboard*` e `/settings*` |
| `auth-cta` | `apps/web/src/components/landing/auth-cta.tsx` | CTA auth-aware: logado → "Go to Dashboard"; anônimo → "Try Demo"/"Try the Demo" |
| `login` | `apps/web/src/routes/login.tsx` | Página de login/cadastro com `beforeLoad` que redireciona logados para `/dashboard` |

## Header e CTAs

- O header usa grid `1fr auto 1fr`: logo à esquerda, nav centralizada, ações à direita.
- `AuthCta` (compacto no header, cheio no hero/CTA) decide pelo `useSession()`: sessão ativa leva a `/dashboard`, senão a `/login`.
- O botão GitHub aparece só na landing (`isLanding`).

## O backend verifica

- Sessão válida em cada request à API
- Membership do projeto (quando `projectId` na rota)
- Papel do usuário (owner/admin/member) para ações restritas

## Dark mode

- Toggle no menu do usuário
- Usa classe `dark` no `<html>`
- Tokens CSS em `packages/ui/src/styles/globals.css` suportam ambos os temas
